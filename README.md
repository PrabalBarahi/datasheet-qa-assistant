# 🔌 Datasheet Q&A Assistant

A web app that lets you upload an electronics component datasheet (PDF) and ask questions in plain English. Answers are generated by an LLM using **only the retrieved parts of the document**, with page numbers cited, so they can be checked.

Built with Python, Streamlit, Sentence-Transformers and any OpenAI-compatible LLM API.

## Why this project
Engineers lose a lot of time searching 100+ page datasheets for one value (absolute maximum ratings, pin functions, timing). This tool applies **Retrieval-Augmented Generation (RAG)** to that problem.

## How it works
```
PDF -> extract text per page -> split into overlapping chunks
     -> embed chunks (all-MiniLM-L6-v2) -> vector index (in memory)

Question -> embed -> cosine similarity -> top-k chunks
         -> prompt = instructions + chunks + question -> LLM -> answer + sources
```

| File | Purpose |
|------|---------|
| `rag.py` | PDF reading, chunking, embeddings and search, LLM call |
| `app.py` | Streamlit web interface |

## Run locally
```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```
Then paste an API key, base URL and model name in the sidebar. Any OpenAI-compatible provider works (for example Groq, Google Gemini's OpenAI-compatible endpoint, or OpenRouter). Check your provider's docs for the current base URL, model names and free-tier limits.

## Deploy (free)
1. Create a Space at huggingface.co/spaces and choose the **Streamlit** SDK.
2. Upload `app.py`, `rag.py`, `requirements.txt` (or push this repo).
3. Visitors enter their own API key in the sidebar, so your key is never exposed.

## Limitations and ideas for improvement
- Scanned PDFs (images) are not supported; adding OCR would fix this.
- Tables in datasheets may be extracted poorly; try a better table parser.
- Add an evaluation set of 20 questions with known answers and measure accuracy.
- Support multiple PDFs and a persistent vector store (e.g. FAISS or Chroma).
